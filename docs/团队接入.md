# 团队内部下载安装

入口：https://apps.example.com/ 。连接公司内网即可使用，无需登录、下载证书或上传 Token。

## 上传与下载

首页只展示团队应用。点击“上传安装包”进入 https://apps.example.com/upload ，选择 IPA/APK 并上传，系统按包标识和 iOS/Android 自动归类；首次上传自动创建应用。同一安装包在同一环境的版本号和构建号都相同时，网页会要求确认覆盖。覆盖保留原版本链接及下载次数，并更新上传时间。

每个产品有汇总页。安装包的固定下载页按测试和正式环境区分，分别展示该环境最新上传的可用版本、历史及二维码。已有的无环境链接继续展示跨环境最新上传的可用版本。独立版本页仍可分享，已归档应用或已停用版本不可下载。

iPhone 使用 Safari，IPA 仍须满足 Apple 签名和设备资格；Android 按系统提示允许安装来源。

## 开发者、AI 和自动化

打开 https://apps.example.com/developers ，在能访问内网的电脑上打开业务工程，把页面指令复制给 AI。AI 可从当前站点获取 CLI，核对工程已有的构建、签名和产物后配置并上传；缺少条件时先说明具体问题。首次上传会自动创建应用，不必预先创建。

如需手动接入，可展开页面的「手动准备接入包」，选择技术栈、核对构建命令与产物路径后下载。项目 Skill、GitHub/GitLab CI 模板和单文件下载仍在可选区域。

配置 `.team-distribution.json` 示例：

```json
{
  "endpoint": "https://apps.example.com",
  "build": ["./gradlew", "assembleDebug"],
  "artifact": "app/build/outputs/apk/debug/*.apk"
}
```

上传无需填写 Git 分支或 Commit；命令行不依赖 Git 安装（存在 Git 时仅可用于默认更新说明）。Python 3.8+，在业务工程根目录执行：

```sh
python3 tools/team_release.py release
python3 tools/team_release.py upload /绝对路径/app.apk
```

release 按工程命令构建再上传，upload 只上传已有包。构建失败、产物未更新或匹配多个文件时停止，不能猜测旧包路径。stdout 是 JSON，含独立版本链接 `release_url`、二维码地址 `qrcode_url`、对应环境的固定链接 `package_url`、产品汇总 `app_url`、文件哈希 `file_sha256` 和 `duplicate`，构建日志走 stderr。

遇到 HTTP 409 时，CLI 会报告版本冲突。确认需要覆盖时，可在网页重新提交，也可通过上传 API 显式提供 `overwrite=true` 和该次冲突响应的 `existing_id` 作为 `overwrite_release_id`。

接入包的 `.agents/skills/team-distribution/` 含中文 SKILL.md、agents/openai.yaml 和 CLI。支持项目 Skill 的 Codex 可调用 `$team-distribution 按工程配置构建并上传测试包`；其他 AI 工具按其目录规范安装同一文件夹，或合并 AGENTS.distribution.md 中的项目规则。无需在平台配置模型或上传业务源码。

GitHub Actions / GitLab CI 模板支持手动或推送指定分支触发，使用能直连 Sunny 的内网 Runner。配置、签名和构建环境沿用业务工程原有流程。GitHub 摘要展示下载链接，GitLab 将 JSON 保留为 Job artifact。生成模板不代表仓库 CI 已启用或真实工程已构建。

仅可在公司内网访问，全局代理设备需让 apps.example.com 直连。平台健康维护、备份在 Sunny 执行；电脑需开机、醒着且已登录。
